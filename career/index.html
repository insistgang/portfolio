CAREER WORKFLOW

求职工作流 Career-Copilot

把「我做过什么」「岗位要什么」「怎么讲」「投到哪一步」拆成四类可维护的数据，再用一条固定链路把它们连起来： 经历证据 → 岗位匹配 → 简历生成 → 投递跟踪 → 邮件回执。系统面向企业求职与学术申请两种场景， 强调每条表述都能追溯到真实证据，而不是写得更漂亮。

公开范围说明

本页只介绍系统的设计思路与功能结构。个人经历主库、投递记录与联系人、简历成品、邮箱内容与实时看板 均不公开：看板服务只在本机 127.0.0.1 启动，接口需要会话令牌校验， 邮件能力通过授权码在本地调用，不向公网暴露任何凭据。

五段链路

经历主库

基础信息、项目卡片与主张—证据账本分开维护，每条强动词都要有支撑证据。

岗位匹配

解析岗位描述或导师方向，提取关键词，从项目卡片中挑选真正对口的经历。

简历生成

Typst 编译单页 A4 技术简历，另提供可在浏览器里微调的 HTML 版本。

投递跟踪

记录网申、笔试、测评、面试与 Offer 状态，并给出投递节奏建议。

邮件回执

本地邮箱读取与 MCP 接口，把面试与测评邀请同步回看板。

关键设计

真实性优先

简历改写只在证据完整的范围内使用「主导」「从 0 到 1」这类强动词；团队协作会写清边界与个人分工， 缺少可核验指标时改用定性描述，不编造百分比、吞吐量或跑分。

双模工作流

同一套经历主库同时服务企业招聘与高校招生：前者强调岗位关键词与项目证据，后者强调研究方向、 方法贡献与实验依据，输出物不同但事实边界一致。

本地优先

看板与邮件能力都在本机运行，静态资源走白名单目录，接口需要随机令牌，投递明细等私人状态文件不进入版本库。

双向反哺

针对新岗位打磨出的项目描述会回写到经历主库，让下一次投递的证据更完整，而不是每份简历都从零开始。

技能入口

/asu

按「动作 → 系统能力 → 业务价值 → 结果证据 → 个人边界」重构经历要点。

/asu-resume

生成高密度单栏技术简历，可视化编辑后导出 PDF。

/resume

在多套 HTML 模板中挑选并微调，输出可编辑简历。

/interview

依据简历与目标岗位预测高频问题，做连环追问式模拟面试。

/offer

记录投递、笔试、测评、面试与 Offer 状态并生成看板。

/contributor

匹配岗位相关的开源项目，准备可用的贡献证据。

技术栈
